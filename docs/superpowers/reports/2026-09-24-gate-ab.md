## Routes

195 routed decisions across 25 tasks: `resolver` 62, `planner` (direct tool step) 57, `planner_pick` (router: planner
chose from the actor's top 5) 22, `actor` 29, `planner_fallback` (planner produced no valid plan; actor-only for
that step) 18, `resolver_fuzzy` 7.

`planner_fallback` fired on 7 of 25 tasks (task-level: the planner returned no valid JSON or a validation error
twice in a row and the step fell back to the actor-only policy). 27 additional single-retry recoveries happened
inline (`invalid plan, retrying once`) without falling all the way back.

`resolver`; the one fuzzy match this run (`turing_references` step 1) was correct.

## Honesty note

8/25 vs. the baseline's 7/25 is a 1-task, 4-point difference — under the ~15-point (4-task) threshold this plan
treats as distinguishable on a 25-task suite. **This run does not show a reliable improvement over the baseline.**
The planner backend changed the failure mix (fewer outright wrong first clicks in some tasks, replaced by a
distinct "planner reached the target but didn't call done" pattern, and a systemic search-box actuation gap
across 5 tasks) without changing the pass rate outside noise.

## Gate verdict

**Gate A+B (≥15/25): MISSED.** 8/25 achieved. No further tuning proceeds without a decision from the user; Phase C
does not start automatically.
